# 写字机串口协议抓包分析

抓包时间：2026-04-25 17:04:37 至 17:04:57  
串口波特率：115200  
协议判断：GRBL 1.1f / G-code 文本协议

## 结论概览

这台写字机使用的是 GRBL 兼容协议，不是专有二进制协议。PC 端通过串口发送 ASCII 文本形式的 G-code，每条命令通常以 `\n` 结尾；设备执行或接收后返回 `ok\r\n`。

核心规律：

- 设备启动后返回：`Grbl 1.1f ['$' for help]`
- PC 发送 `$` / `$\n` 查询 GRBL 配置参数
- 设备返回一组 `$参数=值`，最后返回 `ok`
- 写字阶段主要使用 `G0`、`G1` 和 Z 轴命令
- `G1G90 Z4.0F10000` 表示落笔
- `G1G90 Z0.0F10000` 表示抬笔
- `G0` 是空走移动，速度多为 `F4000`
- `G1` 是写字轨迹移动，速度多为 `F4000`
- 终止阶段会抬笔并回到原点：`G1G90 Z0.0F10000`、`G90G0 X0Y0`

## 连接与初始化

### 设备复位/唤醒

PC 首先发送：

```text
18
```

`0x18` 是 GRBL 的 soft reset 命令，也就是 Ctrl-X。

设备随后返回：

```text
\r\nGrbl 1.1f ['$' for help]\r\n
```

说明控制板固件是 GRBL 1.1f。

### 查询配置

PC 发送：

```text
$
$\n
```

设备返回 GRBL 参数列表，例如：

```text
$0=2
$1=25
$2=0
$3=2
$10=3
$13=1
$30=1000
$31=0
$32=1
$100=160.000
$101=160.000
$102=140.000
$110=8000.000
$111=8000.000
$112=8000.000
$120=2000.000
$121=3000.000
$122=7000.000
$130=200.000
$131=200.000
$132=200.000
ok
```

关键参数含义推测：

| 参数 | 值 | 含义 |
|---|---:|---|
| `$30` | `1000` | 主轴/激光最大值。本次官方抓包未用它落笔，而是使用 Z 轴高度 |
| `$31` | `0` | 最小主轴值 |
| `$32` | `1` | 激光模式开启。虽然机器是写字机，但控制逻辑沿用了 GRBL 激光/主轴开关语义 |
| `$100` | `160.000` | X 轴 steps/mm |
| `$101` | `160.000` | Y 轴 steps/mm |
| `$102` | `140.000` | Z/笔轴 steps/mm |
| `$110/$111/$112` | `8000.000` | X/Y/Z 最大速度 |
| `$120/$121/$122` | `2000/3000/7000` | X/Y/Z 加速度 |
| `$130/$131/$132` | `200.000` | X/Y/Z 最大行程，单位 mm |

## 坐标与模式设置

2026-04-29 针对官方软件“纸张左上角写两个 1”的抓包可反推出纸面坐标到机器坐标的核心规则：

```text
普通模式: X = x_mm, Y = -y_mm
180 度/对角模式: X = paper_width_mm - x_mm, Y = -paper_height_mm + y_mm
```

以 A4 纸和抓包中的首点为例，普通模式 `X20.482Y-11.947` 在对角模式变为 `X189.518Y-285.053`，即 `210 - 20.482` 与 `-297 + 11.947`。

写字开始前，PC 发送：

```gcode
G10 P0 L20 X0.0Y0.0Z0
G21
G90
F4000
G1G90 Z0.0F10000
G1G90 Z0.0F10000
```

含义：

| 命令 | 含义 |
|---|---|
| `G10 P0 L20 X0.0Y0.0Z0` | 设置当前工作坐标偏移，把当前位置设为工作零点 |
| `G21` | 使用毫米单位 |
| `G90` | 使用绝对坐标 |
| `F4000` | 默认进给速度 4000 |
| `G1G90 Z0.0F10000` | Z 轴回到抬笔高度，确保开始前笔处于抬起状态 |

## 写字动作模型

抓包中的写字动作由三类命令组成。

### 空走移动

```gcode
G0 X32.041Y-27.423F4000
```

`G0` 是快速移动，通常用于笔抬起时移动到下一笔画起点。日志中空走速度一般是 `F4000`。

### 落笔

```gcode
G1G90 Z4.0F10000
```

`Z4.0` 是本次官方抓包中实际使用的落笔高度。

### 写字轨迹

```gcode
G1 X32.750Y-27.579F4000
G1 X32.764Y-27.692F4000
```

`G1` 是直线插补移动。落笔后连续发送 `G1` 坐标点，就形成实际笔画。日志中写字速度一般是 `F4000`。

### 抬笔

```gcode
G1G90 Z0.0F10000
```

`Z0.0` 是本次官方抓包中实际使用的抬笔高度。

## 典型笔画序列

一个完整笔画大致如下：

```gcode
G0 X32.041Y-27.423F4000
G1G90 Z4.0F10000
G1 X32.750Y-27.579F4000
G1 X32.764Y-27.692F4000
G1G90 Z0.0F10000
```

解释：

1. `G0` 抬笔空走到笔画起点
2. `G1G90 Z4.0F10000` 落笔
3. 多条 `G1` 连续写出轨迹
4. `G1G90 Z0.0F10000` 抬笔

## 暂停与续写

历史抓包中，17:04:51 左右出现写字暂停：

```gcode
M5
```

随后设备继续返回若干 `ok`，说明之前已经发送进 GRBL 缓冲区的命令仍在被确认或执行。

17:04:54 继续写字时，PC 直接从下一段笔画继续发送。该段来自较早的主轴式抓包，不代表 2026-04-29 本次 Z 轴协议：

```gcode
M3S1000
G0 X33.855Y-29.819F2500
M3S1000
G4 P0.2
G1 X34.181Y-29.819F1500
G1 X34.463Y-29.748F1500
```

这里没有看到 GRBL 标准 feed hold 命令 `!`，也没有看到 cycle start `~`。因此“暂停/续写”更像是官方软件停止继续下发新轨迹，并发送抬笔命令；续写时继续从缓存或任务队列中的下一段 G-code 下发。

需要进一步抓包确认：

- 点击“暂停”的瞬间是否总是只发送抬笔命令
- 是否在其他场景中发送 `!`、`~` 或 `?`
- 暂停时设备是否仍会执行已经进入 GRBL planner buffer 的命令

## 终止/结束

日志末尾的结束动作：

```gcode
G1G90 Z0.0F10000
G90G0 X0Y0
```

含义：

| 命令 | 含义 |
|---|---|
| `G1G90 Z0.0F10000` | 抬笔/停止写字 |
| `G90` | 绝对坐标模式 |
| `G0 X0Y0` | 快速移动回工作坐标原点 |

抓包里 `G90G0 X0Y0` 被连在一行发送。GRBL 可以解析同一行中的多个 G-code word，所以设备仍返回 `ok`。

## 应答机制

设备几乎所有命令都返回：

```text
ok\r\n
```

由于 PC 端会批量发送多条命令，日志里经常能看到多个 `ok` 连续返回：

```text
ok
ok
ok
```

这说明官方软件可能按 GRBL 的串口流控习惯工作：持续填充控制器接收缓冲区，根据返回的 `ok` 推进后续命令。

## 协议复现最小流程

如果自己写控制程序，可以先按以下顺序验证：

```gcode
G21
G90
G10 P0 L20 X0Y0Z0
G1G90 Z0.0F10000
G0 X10Y-10F4000
G1G90 Z4.0F10000
G1 X20Y-10F4000
G1 X20Y-20F4000
G1G90 Z0.0F10000
G90G0 X0Y0
```

发送策略：

- 串口：115200
- 编码：ASCII
- 行结束：`\n` 即可，`\r\n` 也通常可用
- 每条命令等待 `ok` 更稳妥
- 如果要提高速度，可以实现 GRBL streaming buffer，但初期建议一发一等

## 后续建议

为了把协议摸得更完整，建议继续分别抓这些动作：

| 动作 | 重点观察 |
|---|---|
| 单独点击暂停 | 是否发送 Z 轴抬笔、`!` 或其他控制字符 |
| 暂停后继续 | 是否发送 `~`，还是继续发送普通 G-code |
| 手动移动 X/Y | 是否使用 `G0` 或 jog 命令 `$J=` |
| 调整笔压/速度 | Z 高度、`F` 数值是否变化 |
| 回零/复位 | 是否使用 `$H`、`G10`、`G92` 或 Ctrl-X |
| 断点续写 | 是否重新设置坐标偏移或直接续发轨迹 |
